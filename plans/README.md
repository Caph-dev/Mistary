## 依赖与交付边界

- 001 先隔离应用身份、数据和所有旧更新/授权入口，之后才能运行个人应用做实验。
- 002 和 003 逻辑上可以分别推进；默认顺序执行，避免同一工作区并发写入。002 交付实际支持 app/版本/模式/操作清单；003 交付目标快照与动作结果契约。
- 004 只交付 Finder 上下文、目录候选、收藏和严格 scope。005 消费目录候选并执行对话框导航；004 不反向依赖005。
- 精确目录 scope 必须在搜索候选排序、topK、空查询 recent 之前生效，并进入缓存条件。004允许最小中性核心扩展；保持默认全盘行为、SoA、C和索引格式。此项是对总方案“主要扩展应用层”的正确性细化，不重写搜索内核。
- 006依赖003的会话/执行契约，不要求对话框自动化先成功。网页和命令不能伪装为 SupplementaryHit。
- 007依赖006的结果/配置类型，008只依赖003动作事件与004 scope、006身份；新增动作统计无需阻塞基础历史。
- 009窗口代码可以独立推进；完整日用验收必须等全部前置阶段，不能用只完成窗口偏好代替产品验收。

本轮没有创建或委托子代理。日后若并行实施，必须由操作者授权，且一个工作区只能有一个写入者；逻辑上可并行不代表可同时改共享 AppDelegate/SearchViewController。

## AX 关卡与首版范围

001～005组成首版的实施范围。

- **PASS**：至少两个常用应用有可重复导航，其中至少一个真实Save面板保持文件名；005仅启用验证清单内的操作。
- **PARTIAL**：005按app、模式、操作分别开放；不支持部分提供手动交接。
- **FAIL**：005实现搜索、收藏和显式复制路径的手动路线。仍可继续006～009，但自动对话框目标标为未完成。

自动或手动路线都不得自动提交Open、Save或覆盖确认。Save保持原文件名；取消后不继续派发步骤，但无法撤回已交给系统的操作。预期焦点交接允许，意外切换取消。快照截图不证明第三方应用兼容。

## 共同实施规则

每份计划已内联以下约束，执行时也需遵守仓库 AGENTS.md。

- macOS 14、Apple芯片、Swift5、系统框架；保留现有target名，不引入第三方包。
- 首先查看当前工作区和基底差异；前置计划的改动需核对交付契约，无关改动保留。
- 不引入公开库对私有模块的依赖；保留MIT原作者声明，不改site/Pro。
- 注释英文；L10n中文/英文成对维护；索引读锁内不做I/O，热循环不逐项String/堆分配。
- 一次捕获的动作校验同一文件目标，不拿后来选中的行代替；accepted不代表目标app已读取文件。
- 文件修改不覆盖，默认删除进废纸篓。真实安装/卸载、证书创建、Git提交/推送不自动执行。
- 规划阶段未运行 Swift 测试、构建或真实 AX 实验；001、002、003、004、006 实施后的实际验证记录分别见 [隔离证据](evidence/001-isolation.md)、[AX 证据](evidence/002-ax-compatibility.md)、[会话及动作证据](evidence/003-search-session-actions.md)、[Finder／范围／收藏证据](evidence/004-finder-scope.md) 与 [启动器路由证据](evidence/006-launcher-query-routing.md)。005、007～009 的命令与新增测试仍为未来验证项。测试零匹配不算通过。
- 更新状态需有可读证据。建议将实际记录写入各计划指定的 `plans/evidence/`；本轮不预建空证据或伪造支持清单。

## 验证层次

1. 每个步骤运行其最窄测试或脚本夹具；新类先创建再运行。
2. 每阶段结束做release构建、diff检查和范围检查。脚本测试隔离所有外部副作用，不能真实卸载原应用。
3. AX/Finder兼容性必须用真实目标app验收，记录系统与app版本；失败记录不能改成未验证或通过。
4. 最终阶段跑完整Swift、公开模块边界、身份/安装/卸载夹具，另记录实际日用与同机性能。

规划阶段只验证计划文件的结构、依赖、链接、引用和范围；实施后的功能与验证完成度以各项状态和证据文件为准。
